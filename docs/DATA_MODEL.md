# Data Model

## Supabase: `entries` table

The app uses a single table. One row per movie or TV show being tracked.

| Column | Type | Constraints | Notes |
|---|---|---|---|
| `id` | `uuid` | PK, default `gen_random_uuid()` | Generated by Postgres |
| `title` | `text` | `not null` | Required |
| `year` | `integer` | nullable | Release year |
| `genre` | `text` | nullable | Single genre, free text (datalist suggestions in UI) |
| `type` | `text` | nullable, `check in ('movie', 'tv_show')` | |
| `status` | `text` | nullable, `check in ('watched', 'want_to_watch', 'currently_watching')` | Required by the API on create |
| `watch_date` | `date` | nullable | Typically set when status is `watched` |
| `rating` | `integer` | nullable, `check between 1 and 10` | |
| `notes` | `text` | nullable | Empty/absent notes are stored as SQL `NULL`, never the string `"null"` (see `sanitizeEntry` in `api/_supabase.js`) |
| `created_at` | `timestamptz` | default `now()` | Used for default sort (newest first) |

### Indexes

- `entries_created_at_idx` on `(created_at desc)` — default list sort.
- `entries_status_idx` on `(status)` — supports status filtering.

### Row-Level Security

RLS is **enabled**. One policy:

```sql
create policy "Allow anon full access to entries"
  on entries for all
  to anon
  using (true) with check (true);
```

This is a single-user personal app with no authentication. The anon key (held only by the serverless API) has full read/write access. Do not store sensitive data.

### Migration

Applied via Supabase migration `create_entries_table`. See the `create table entries (...)` DDL plus the two indexes and the RLS policy above.

## Client-side state (`localStorage`)

No entry data is stored client-side — only UI preferences:

| Key | Purpose | Example value |
|---|---|---|
| `reel.sort` | Last selected sort option | `created_desc`, `watch_desc`, `rating_desc`, `year_desc`, `title_asc` |
| `reel.filter` | Last selected status filter tab | `all`, `watched`, `want_to_watch`, `currently_watching` |

## Derived data (computed in the browser, not stored)

The Stats view computes everything from the loaded `entries` array:

- **Total watched** — count where `status = 'watched'`.
- **Average rating** — mean of `rating` over watched entries that have a rating.
- **Movie vs. TV split** — counts of watched entries by `type`.
- **Top genres** — frequency of `genre` among watched entries, ranked.
- **Watched per year** — grouped by `year(watch_date)`.
- **Watched per month** — for the most recent year that has watch dates, grouped by month.
